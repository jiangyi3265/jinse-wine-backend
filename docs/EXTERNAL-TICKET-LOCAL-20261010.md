# 第三方门票奖品（本地版本）

后续状态：用户在本地预览后授权上线，2026-10-10 16:29 已部署管理端、Java 和 H5，微信开发版本 `1.0.20261010.1630` 上传成功。详见 `evidence/20261010-external-ticket-deployment.md`。以下“未部署”及局域网设置是此前本地验证阶段的记录。

## 实现范围

- 奖项新增“第三方门票”，每次中奖发放一张独立门票。
- 运营中心 → 扫码抽奖 → 新增奖项，保存后在该行进入“门票库存”。
- 支持一次选择多张 PNG/JPG 图片，逐张填写售票方唯一票号；统一填写售票方和有效期。
- 最大 2 MB，图像尺寸 64 至 4096 像素；检查图片格式、图像可读性、重复图片和重复售票方票号。
- 原始票码以私有数据库 BLOB 保存，不经过公开图片上传接口、不裁剪、不重绘。
- 库存以实际可分配票数为准，忽略门票奖项通用 stock 输入，不支持无限门票。
- 生成抽奖码时按原有概率固定结果，同时锁定一张尚未分配、未过期的门票；没有可用门票时为未中奖，不提高其他奖项概率。
- 同一生成请求重试返回同一批次，不重复锁票。
- 用户中奖后在“我的奖品”和抽奖记录查看原始票码；二维码接口验证会员身份和奖品归属。
- 支持并发防重、领取请求幂等；已发放门票永久绑定，不能通过停用或过期回收给其他用户。
- 未领取抽奖码过期时，通过现有过期任务释放仍有效的预留门票；门票本身过期则标记过期。
- 门票不可通过我们系统的门店核销员核销，核销交由售票方。
- 抽奖财务报表结果类型显示“第三方门票”。

## 状态和约束

门票库存显示：待分配、抽奖码预留、已发放、已停用、已过期。
本期不接收售票方核销状态。用户页面显示“已发放”和“使用状态以售票方验票结果为准”。
原始二维码有效性、实名绑定、是否允许转赠和重复使用限制由售票方负责。
我们仅校验图片可读性，不调用售票方接口，不保证任意图片包含其认可的有效门票。
票号必须使用售票方实际唯一编号；相同二维码经过裁剪/截图等修改后，不能仅依靠文件哈希识别重复。
用户奖品有效期取活动奖品有效期和售票方门票有效期中的较早时间。
