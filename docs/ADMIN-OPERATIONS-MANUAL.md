## 访问与账号

- 线上管理端：`https://jiuyeklht.oksja.cn`
- 地址：`http://127.0.0.1:5178`
- 默认超级管理员：`admin` / `admin123`
- 后端地址：`http://127.0.0.1:8080`
- 数据库：`jinse_wine`，MySQL `127.0.0.1:3306`

本地服务一键启动：在后端目录执行 `powershell -ExecutionPolicy Bypass -File .\bin\start-local.ps1`；停止执行 `.\bin\stop-local.ps1`。脚本会在后台启动 Redis、后端 JAR、管理端和 H5，不依赖当前 CMD 窗口保持打开。

本地 H5 默认使用普通会员身份 `local-dev`；需要联调门店核销流程时可将小程序登录码切换为 `local-staff`，该身份会绑定 `MINI_LOCAL_STAFF_STORE_ID` 指定的已启用门店（默认门店 1）。两种身份只在 `MINI_LOCAL_LOGIN_ENABLED=true` 时生效，生产环境必须关闭本地登录。

首次部署后请立即修改默认密码，并按生产环境要求替换 JWT 密钥、微信支付证书和上传目录。

### 配置业务角色账号

线上已提供“账号与权限”菜单，仅超级管理员默认可见：

1. “后台账号” → “新增”：填写用户名称（登录账号）、昵称和密码，选择归属部门及财务、运营或核销员角色后保存。后台账号列表支持修改、停用、重置密码和分配角色。
2. “角色管理”：查看角色权限和数据范围。不要给普通业务角色授予后台账号管理权限。
3. “部门管理”：维护门店对应的组织部门；核销员后台账号所属部门须与门店的核销员部门 ID 一致。

后台账号与小程序会员分别管理。小程序会员首次微信登录自动建档，在“业务管理 / 会员管理”查看；小程序核销员在会员状态操作中绑定所属门店。

如果新环境缺少上述入口，在后端目录执行以下幂等脚本；脚本不创建用户、不修改现有角色授权，可重复运行：

```powershell
$adminCredential = Get-Credential -UserName admin -Message '请输入现有超级管理员凭据'
.\bin\provision-account-menus.ps1 -ApiBase 'https://jiuyeklht.oksja.cn/prod-api' -Credential $adminCredential
```

数据库迁移只创建 `finance`、`operator`、`verifier` 三个角色，不预置弱密码账号。首次验收或部署到新环境时，在 PowerShell 执行：

```powershell
cd D:\zhangq\jiuye\jinse-wine-backend
.\bin\provision-role-users.ps1
```

脚本会提示管理员密码和三类业务账号密码，然后通过后台接口创建或更新账号、绑定角色并启用账号。密码只在当前 PowerShell 进程内存中使用，不写入脚本、数据库明文或日志。核销员账号的所属部门必须映射到门店的 `dept_id`，否则按设计只能看到空数据。

需要 Windows 登录后自动启动本地服务时，在后端目录执行 `powershell -ExecutionPolicy Bypass -File bin/install-local-autostart.ps1`；取消自动启动执行 `powershell -ExecutionPolicy Bypass -File bin/uninstall-local-autostart.ps1`。

## 日常运营顺序

会员首次微信登录建档后获得独立于数据库 ID 的唯一会员编号；昵称或头像不完整时会显示资料完善入口，须由用户主动选择头像、确认昵称。资料保存后在“会员管理”查看昵称和头像图片；已有资料不会因再次登录被默认值覆盖。需要修改时，小程序进入“我的 → 个人资料”，手机号可编辑保存。后台详情不展示 OpenID、UnionID 或头像地址。此前版本 `1.0.20261007.4` 为历史记录，当前体验版须在公众平台核对。

财务报表统一中文状态、结果类型、履约方式及是否追偿字段，下载文件名也是中文。所有金额使用元并保留两位小数；涉及会员的导出使用会员编号、用户名，不显示内部用户 ID。原交易号、业务编号保持原值。刷新管理端后重新导出，旧 CSV 不会自动修改。

“财务报表”分销售订单、商城退款、退货入库、佣金明细、佣金提现、抽奖记录、核销记录、销冠奖励、微信小店退款九个页签。每页独立保留日期、会员编号、会员名、关键字、状态和分页条件；微信小店退款无本地会员关联，只有对应业务筛选。填好条件后点“查询”，导出使用最近一次已提交的查询条件并包含全部匹配行，不仅当前页。销售订单按商品逐行展示，订单金额、优惠、运费、退款和净额只在第一行计入，跨页也不重复计账；详情可查看完整字段。

“退款售后 → 退货换货”可按申请日期、会员编号、类型、状态，以及售后单/订单/商品/用户名关键词查询，翻页保留已查询条件，可访问 200 条以后的记录。点击“查看 / 处理”审核并填写退货地址；会员填写寄回物流后，仓库确认收齐数量，填写其中可售入库数量和必填收货凭证。凭证和数量提交后不可通过重复请求改写。退货退款生成已审核的退款单，仍须在商城退款页完成真实资金流程；换货须另行发出新商品并由会员确认收货。“退货入库流水”同时包含本流程和旧退款后收货登记，新增入库来源、售后单号和售后类型，换货退款金额为 0.00 元。历史未填写凭证的记录保持原样，不伪造补写。

会员从订单详情进入“售后记录”时，每页 20 条，底部箭头翻页，显示总数和页码。申请页的“最多几件”由后端汇总全部有效售后及旧退货数量，不受正在查看第几页影响。已驳回或撤销的售后释放数量，已完成售后继续占用原商品数量；查询失败需重新加载后再提交。

商品分类先在“业务管理 → 商品分类”中新增，再在商品新增/修改表单的“商品分类”下拉框按名称选择，也可输入名称搜索。分类编码自动生成，名称不可重复，可调整排序和启停状态。修改分类名称会同步已有商品的分类显示；停用后不能用于新增商品或切换分类，但已有商品可保留原分类继续编辑。分类列表显示商品数量；有商品引用时不能删除，须先将商品移到其他分类。原来的分类文字已自动迁移到独立分类记录，小程序仍按对应分类名称展示。

6. 在“VIP 社群”保存活动，选择小程序订阅通知、企业微信群或两者同时发送。订阅通知只投递给主动授权且有可用额度的会员；企业微信群按渠道配置中的目标群 ID 独立建立投递任务。
7. 在“分销配置”和“销冠排行”确认佣金梯度、结算等待期、排行榜周期和奖励。榜单最终结算只能选择已结束的周/月/季，或此前保存的完整自定义时间段；“结算周期奖励”会固定该周期排名，包含空周期，重复结算不会重复发积分。周期最终结算后的退款不会自动扣回已发积分，请由财务按追偿规则复核。销冠补贴线下发放后，点击“确认补贴已发”并填写转账单号/财务凭证号；提现审核通过后，财务完成实际转账，再确认“已转账”。
8. 在“退款售后”区分业务审核和微信资金状态。微信退款处于处理中、未知或异常时先查微信单，禁止线下确认；只有无微信退款记录或平台明确关闭后，财务实际付款并填入付款凭证号，才可人工确认已退款。后台记录确认人和时间。已退款且有发货/自提核销记录的订单可点击“退货收货”：填每件商品的实收数量及其中可再次销售的数量，并填写收货凭证。损坏品的可售数量填 0；已登记数量不能超过原订单数量，重复请求不会重复入库。微信小店售后进入独立退款对账台账，不会直接修改本地商城账本。
9. 在“财务报表”选择日期范围导出销售、商城退款流水、退货入库流水、佣金、提现、销冠奖励、抽奖、核销和微信小店退款对账 CSV。每项导出入口标明日期筛选依据：订单按下单时间，商城退款/提现按申请时间，退货入库按收货时间，佣金/抽奖/核销按记录时间，销冠奖励按周期开始时间，微信小店退款按台账更新时间。销售订单含履约方式、支付时间、微信支付交易号、应付、已确认退款和本地净额；仅“已退款”计入确认退款。商城退款流水含商户退款单号、微信退款单号、渠道状态及线下付款凭证、确认人和时间；退货入库流水含商品、实收、可售、不可售数量与收货凭证。人工登记和本地净额不能代替微信或银行流水，财务仍需逐笔对账。

在“积分兑换”维护兑换项时，优惠券类型须关联启用且在有效期内、有库存的券模板；实物可指定一家已启用门店，留空则合作门店均可核销。库存 `-1` 表示不限量，`0` 表示暂不可兑换。券模板或指定门店停用后，对应兑换项不会在小程序兑换目录展示；已发出的奖品仍按发放时记录的门店范围核销。

### 后台角色与门店数据范围

- 财务角色可查看订单、退款、佣金和报表，但不能维护商品、活动或渠道配置。
- 运营角色可维护商品、门店、活动和渠道，不包含财务报表导出及佣金提现查询。
- 核销员角色的后台记录按“用户所属部门 -> 门店管理中的核销员部门 ID”过滤。给核销员后台账号分配部门后，在对应门店选择同名所属部门；未完成绑定时默认不返回订单、会员、奖品和核销记录，避免看到其他门店数据。

## 核销流程

### 开通小程序核销员与实物奖品交付

1. 核销员先用本人微信登录小程序，生成会员记录。后台管理员进入“业务管理 / 会员管理”，按会员编号、昵称或手机号定位该会员。
2. 点击该会员“处理”，目标状态选择“保持启用”（停用会员选择“启用”），在“核销员所属门店”选择已启用的合作门店，再点“确认处理”。后台登录账号和小程序微信会员是两套身份，后台角色不能代替此门店绑定。
3. 核销员重新进入小程序“我的”，看到“门店核销”入口；若未刷新，退出登录后重新微信登录。页面顶部应显示实际绑定门店。
4. 顾客进入“我的 / 我的奖品 / 待兑换”，展开对应实物奖品并出示兑换二维码。应扫描个人奖品兑换码，不扫描瓶身抽奖码。
5. 核销员进入“门店核销 / 实物奖品”，点“扫码核销”，核对名称、规格、领取人和待核销状态。交付实物后点“确认核销”并确认弹窗。无法扫码时可输入顾客页面上的兑换码查询。
6. 核销成功保留已核销结果，最近奖品核销及后台核销记录可追溯本次交付。已核销、过期、门店范围不符、会员或门店停用的请求由后端拒绝。清空会员门店绑定即取消小程序核销员资格。

核销查询结果独立于核销员自己的“我的奖品”；修改输入、重新查询或切换类型时清除旧结果，连续查询只展示最后一次响应。提交期间不能切换对象，提交结果未知时对同一奖品重试沿用原请求号。H5 API 模式使用手工输入；真实相机扫码须在微信小程序验证。

### 平台配送发货

“业务管理 / 订单管理” → 订单“详情” → “填写发货信息”：选择快递公司、填写物流单号后保存，订单立即进入待收货；无需手工填写物流状态。支付完成且未发货的配送订单显示待发货；轨迹尚未取得时显示暂无物流信息，不影响发货后的待收货分类。后台定时查询微信物流；该接口目前仍需管理员开通权限，未开通或查询失败不会伪造轨迹或签收。取得真实签收时间后七天才可自动确认收货，退款售后中的订单受业务校验限制。仅已支付的平台配送订单可首次发货；门店自提订单由指定门店核销员扫码交付。

- 实物奖：会员展示奖品码，核销员只能查询所属门店可核销的奖品；确认后一次性写入核销流水。
- 门店自提：会员付款后展示订单核销码；核销员门店必须与订单指定门店一致。确认会同时完成订单、优惠券、积分和佣金，重复请求返回原结果。
- 现金奖：只有微信商户转账成功回调或查单成功才显示到账；处理中、未知和失败状态不能人工改成成功。

## 微信渠道配置

### 客服人员在哪里回复

小程序“联系在线客服”调用微信原生客服按钮。接待人员登录 https://mp.weixin.qq.com/ 对应小程序，在“功能 / 客服”（以当前平台菜单为准）添加并绑定客服微信号；随后用该微信登录 https://mpkf.weixin.qq.com/ 选择小程序接待，也可以使用微信官方“小程序客服”小程序。用户要先进入客服会话并发送消息，客服人员再按平台支持的会话时效回复。

酒业后台“微信渠道 / 在线客服二维码”只管理页面展示的二维码，不负责收取和回复微信客服会话。用户长按识别该二维码后，由二维码对应的微信或企业微信账号接待。后台超级管理员账号不能代替微信客服身份。找不到会话时，先核对客服绑定的小程序 AppID、接待微信号及用户是否实际发送消息。客服账号绑定及真实消息收发仍需要运营人员完成验收。

### 门店位置配置的版本区别

线上已支持省市区联动。下一次门店地址解析更新已在本地完成：新增/修改门店只填写省市区和详细地址，后台保存时自动解析位置。该后端更新需要 `TENCENT_MAP_KEY`，当前等待提供，尚未部署；开通与业务规则见 [门店地址与距离说明](STORE-LOCATION.md)。不要把本地构建完成当作线上自动解析已接通。

真实支付、红包、官方小程序码、企业微信群码和微信小店需要正式资质、HTTPS 回调和平台白名单。配置不完整时接口会返回明确错误；不要用数据库手工改成成功状态。

企业微信群码的链接、平台配置 ID、生成时间、有效期和旧码撤销状态由生成/轮换服务维护，通用渠道保存接口拒绝直接修改；小程序不展示缺少有效期或已经过期的群码。轮换完成后在企业微信真机扫码确认目标群，再查看旧码撤销状态。

旧码撤销失败会留在待重试清单，定时任务下次运行时逐个重试；后续再次轮换不会覆盖此前失败的旧码。若企业微信显示已删除，但后台仍显示待重试，可能是撤销成功后的本地确认写入失败。先在企业微信管理端按 `config_id` 核验，再在“微信渠道 / 企业微信群二维码”待处理列表点击“登记已撤销”，填写平台检查时间、操作记录或工单号。后台只允许处理待清单中的旧码，不允许把当前生效码标记为已撤销；操作人、请求证据和时间保存在若依操作日志。不要仅凭一次接口失败清空待撤销清单。当前本地没有企业微信正式凭据，不能把测试接口结果当作真实撤销验收。
