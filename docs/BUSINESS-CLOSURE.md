# 定制酒业小程序代码交付对照（非生产验收结论）

本文区分代码内业务流与正式环境交付。表中存在页面、接口、状态表或配置项，不代表相应外部平台已连通，也不代表资金已经真实支付/到账。只有完成文末所列外部授权、迁移和联调后，相关合同项才可按生产闭环验收。

## 2026-10-07 商品规格关联

商品规格按商品 ID 关联，独立菜单管理售价、库存与状态；商品列表和运营中心可进入同一商品的规格。微信小店 SKU ID 在运营中心单独保存，后端只更新本次变更的映射并检查旧值、所属商品和重复占用；商品规格列表编辑期间发生新增或删除时拒绝旧版本保存。更换微信小店商品 ID 会清空该商品的旧 SKU 映射。隔离回归与本机联调范围见 `FUNCTIONAL-TEST-REPORT.md`。2026-10-07 已发布线上接口和管理端，线上管理员可见“商品规格”菜单，选择“典藏酱香”可在规格页与运营中心看到同两条 SKU；发布回执位于服务器 `/www/backup/jinse-wine/before-sku-mapping-20261007/deployment-receipt.json`。当前该商品尚无微信小店商品映射，真实平台 SKU 绑定与库存对账仍待微信小店授权及商品发布后验证。

## 2026-10-06 商城退款库存

- 退款确认事务仅在订单从 `paid` 转为 `refunded` 且累计已退金额达到订单全额时回补订单明细数量；SKU 同步状态置为 `pending`，由现有微信小店库存任务对账。重复确认、部分退款、已发货/已完成和已取消订单不重复回库。部分金额退款对应的退货数量、发货后退货入库需另行确认业务口径与验收。

## 2026-10-06 退款人工确认审计

- 商城退款的人工“已退款”确认仅允许在没有微信退款记录，或微信退款已明确关闭时执行；微信处理中、未知和异常状态先查单，避免微信与线下双重付款。
- 财务必须填写实际线下付款凭证号；服务端记录确认人和付款时间，退款列表及逐笔 CSV 同步展示。确认动作仍只代表人工登记，需与银行流水核对。旧库执行 `sql/business-refund-audit-upgrade.sql`；当前数据库快照已包含三个审计字段。

## 本轮复核修正（2026-10-05）

- 本地自启动脚本按后端目录接口就绪后再启动前端，H5 目录加载同时提供退避重试，避免服务重启期间误显示无商品。
- 微信退款回调必须同时匹配平台签名、商户号和小程序 AppID；缺少 AppID 的不完整报文不会改变本地退款状态。
- 退款请求幂等现在校验会员、订单号、金额和标准化原因；相同请求号只有载荷完全一致才回放原申请，否则返回 409。退款申请先锁定会员行，再锁订单并校验累计未决/完成金额，避免同一会员并发退款超额；唯一索引冲突时回读原申请处理重放。临时订单回归已覆盖同请求号重放、改金额/原因冲突、跨订单并发重用请求号以及并发退款金额上限，所有临时订单与申请已清理；该验证不包含微信实际退款及资金到账。
- 佣金提现审计闭环要求人工登记实际转账凭证后才能确认 `paid`，退回提现必须填写原因；凭证与原因在管理列表和财务导出可追溯，退回仍会释放关联佣金流水。此流程记录人工线下操作，不代表已接通或收到银行/微信商户转账回执。

- 社群活动的计划发送时间现在由服务端统一解析为 `YYYY-MM-DD HH:mm:ss`，拒绝非法日期和早于当前时间的计划；入库使用标准时间类型，避免错误时间让活动进入无法投递的草稿状态。
- 端到端复核确认抽奖可复用码、实物奖品核销、配送确认收货和门店自提均按事务完成状态流转；重复请求号不会重复发奖、核销、积分或佣金。测试数据已在复核后删除，生产数据未被混入。
- 管理端运营页在 600px 以下增加表单控宽、按钮换行和横向溢出保护，窄屏下抽奖、分销、渠道和报表操作仍保持可操作。
- 抽奖前台奖项目录现在复用实际发奖的优惠券有效期、状态和库存过滤条件，避免出现“目录可见但中奖后无法发券”的业务断链。

- 本地演示门店已补齐地址、电话和经纬度，API 与离线预览均可显示“营业中”，地图、拨号、导航和后台门店维护入口形成完整可验收链路；正式环境仍需替换真实门店资料。
- 小程序推广团队零成员时显示完整空状态和推广海报入口；本地会员收货地址已补齐为可读地址，避免上线截图出现“示例收货地址”占位文案。
- 规则页种子文案已补齐配送、活动、积分、排行、推广、抽奖和优惠券的关键说明；迁移只更新 `create_by=seed` 的初始记录，运营已编辑内容保持不变。
- 后台门店数据范围扩展到写操作：目录编辑/删除、订单发货、订单/奖品/会员状态变更均先复用门店范围谓词校验目标记录；核销员不能通过直接 ID 操作其他门店数据。
- 购物车结算请求号在成功结算后会清空购物车；服务端重试会比对履约方式、自提门店、优惠券和地址快照，只有同一结算目标返回原订单，复用请求号提交其他结算目标会返回业务冲突。地址快照比较按 JSON 结构处理，兼容 MySQL 的格式规范化。
- 修正核销员读取范围：兑换门店留空的奖品表示所有合作门店可核销，现在对已绑定门店的核销员可见；指定兑换门店的奖品仍严格按门店部门范围过滤。

- 修正 VIP 社群双通道状态竞态：企业微信群 worker 回收超时任务时，现在与小程序订阅通知共用两张投递表计算活动状态；任一通道仍有待发送/重试任务时，活动不会提前标记为失败或完成。
- 补齐奖品有效期边界：活动 `rule_json.rewardValidityDays` 可配置现金/实物奖领取有效期（0-3650天，0 表示不限制）；会员查询、领取现金红包、门店查询/核销实物奖品前，服务端会关闭已过期且仍处于待处理、处理中或发放失败状态的权益；已到账/已核销历史记录仍可查看，过期权益不能重新发放或核销。后台批量生成抽奖码纳入数据库事务，批量写入失败会整体回滚。
- 抽奖活动编辑页已将二维码复用和奖品有效期改为可视化控件，扩展 JSON 仅保留高级参数；后台保存会校验优惠券模板有效期和库存，抽奖时再次过滤失效券，避免中奖后才失败。
- 平台配送补齐后台发货闭环：订单详情可填写/更新快递公司、运单号和最新物流说明，服务端校验履约方式与订单状态后写入 `biz_order_delivery`；已支付订单保存发货信息自动进入待收货，小程序订单详情回读同一物流摘要和状态轨迹。
- 处理订单取消与微信支付回调竞态：取消事务与支付通知按订单行锁串行；若成功支付通知晚于订单取消，保留支付流水并自动创建全额原路退款任务，调度器提交微信退款。配置缺失时任务保持排队，网络结果未知时停止自动重发并要求先查微信退款单。
- 客户端写操作统一保留稳定请求号：支付预下单、订单取消/收货、退款、提现、领券、签到、积分兑换、抽奖和红包领取在网络超时后重试会复用原请求号；服务端签到写入营销幂等表，支付预下单写入 `biz_order_pay_request` 并回放已保存参数，退款与提现继续由业务唯一键返回原记录。
- 订单取消和确认收货分别记录 `cancel_request_id`、`receive_request_id`；同一动作的重放直接返回订单，避免重复释放库存、锁券或发放收货积分。
- 小程序确认订单按履约方式校验目标：平台配送要求收货地址，门店自提要求有效自提门店，不再因缺少配送地址阻断自提报价；门店目录公开数据库 `storeId`，自提报价使用同一数字 ID 完成门店名称、地址和运费计算闭环。
- 管理端运营工作台的统计卡片、趋势图、表格和页签改用主题变量，暗色主题下的文本与背景保持可读，移动窄屏布局继续保留。
- 财务报表的门店核销导出统一抽奖核销与商城自提核销的 UTF-8 排序规则，避免不同表结构做 `UNION` 时返回 500；导出结果和日期筛选审计可追溯。
- 认证和视觉复核：全局 JWT 过滤器跳过小程序 URL-safe 会话串，避免会员请求产生误解析日志；个人中心头像统一走服务端媒体地址并在缺失或加载失败时回退到品牌素材。
- 多笔退款并发复核：同一订单存在任一待审核或已批准退款时，未提现佣金保持冻结；每笔实际退款按订单累计退款比例调整佣金，只有全部未决申请完成或驳回后才恢复剩余佣金。后台审核与完成流程先锁所属订单，避免并发审核与退款回执交错造成过早解冻。
- 已提现佣金退款追偿：按退款策略为已提现佣金生成负向佣金流水，推广中心展示待抵扣/已抵扣状态和负金额，冲减推广员后续可提现净额；提现锁定同一会员的正负佣金流水，申请失败时完整释放，财务确认打款后将追偿项记为已抵扣并清除对应追偿标记。提现退回必须写原因；人工确认线下转账必须保存付款凭证号并记录付款时间。该状态只代表登记了人工线下付款，不是银行或微信商户转账回执；无后续佣金时负余额留在账上，不生成虚假支付。
- 佣金结算时序：新增独立定时任务按配置结算周期推进到期佣金；推广中心查询和提现接口也会先补做一次到期结算，提现按会员行锁串行化，重复请求号返回原结算单。
- 实物奖品兑换门店闭环：抽奖奖项和积分实物兑换项均可选定一家启用合作门店；留空表示全部合作门店。发奖时将门店范围快照写入 `biz_reward.redeem_store_id`，核销查询展示门店，确认核销按核销员所属门店拒绝跨店操作；旧数据保持 NULL 并按全部合作门店处理。
- 分销关系深链修正：绑定上级时完整遍历现有关系链，只拒绝绑定本人、自己的下级或历史循环；已有更深上级不会因为超过 `max_level` 被误拒。`max_level` 仍只控制确认收货时实际发放的佣金层数，客户/员工费率和梯度不变。

- 排行榜净业绩口径修正：前台榜单和后台发奖均排除周期内净佣金小于等于 0 的会员，退款追偿负向流水只用于冲减业绩，不会让负业绩进入奖励名次。

- 排行榜最终结算改为周期级事务：按结束时间冻结净佣金名次、规则和积分奖励；相同配置/周期并发或重复请求只返回同一结算快照。包括无人获奖的空周期也冻结；拒绝未结束和与历史结算重叠的周期，后续退款不会触发二次改榜；已发积分的迟到退款须财务按追偿规则复核。

`business-role-seed.sql` 按角色标识补齐财务、运营和核销员岗位，并授权业务菜单；它不创建登录账号，须在业务菜单脚本之后执行。`repair-seed-encoding.sql` 仅用于修复已有旧演示数据的乱码，新库初始化无需执行。
