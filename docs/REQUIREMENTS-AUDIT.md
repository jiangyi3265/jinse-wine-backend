## 审核结论

当前实现已经覆盖主要页面、数据模型和多条服务端业务流，但不能据此认定合同列出的 13 项全部可验收。商城支付与退款到账、微信红包转账、扫码抽奖码批量生成、真实社群触达、企业微信群活码、视频号/微信小店同步等依赖微信侧资质、凭据、回调或第三方服务；本地代码不能替代这些外部能力。本机已配置并验证小程序 AppID/AppSecret，可获取微信 access token；商家转账适配器现已接入，但必须开通商户转账产品并配置真实场景、凭据及公网回调，仍需真机和资金联调。推广海报已实现官方小程序码生成与邀请码归因代码，仍须确认正式发布页面、域名白名单并实机验证。当前本地 `jinse_wine` 数据库已执行最新版迁移并完成新增表检查，正式环境仍需按同一脚本部署。

本审核把“接口和页面存在”与“业务可在正式环境闭环”分开。状态为“部分实现”的项目必须按本表补齐并完成联调后才能验收。

- 后台退款审核与实际资金退款分开；仅人工确认已退款后更新实际退款累计。全额退款才把订单改为退款完成。

## 需求完整性复核与逐项验收闭环

原始清单覆盖了主要模块，但“自动、一键、全部、互通、长期有效”等描述不是可执行的验收标准。下表给出每项至少应核验的前台入口、后端结果和异常边界；标记为“外部依赖”的部分必须接入真实微信/企微能力并收到可信回执，不能以页面提示、数据库入队或人工改状态代替。

| 模块 | 验收闭环与异常边界 |
| --- | --- |
| 扫码抽奖 | 后台配置活动时段、个人/每日次数、奖项概率与库存并生成码；用户授权登录后扫码，服务端原子扣次数/库存并按会员请求号幂等落抽奖流水；普通活动码只能使用一次，可复用活动码允许多条流水但仍受活动/会员限制；实物奖只能由授权门店核销员核销一次，现金奖须以微信转账成功回调记到账。重复扫码、库存耗尽、活动过期、概率配置不合法均须给出确定结果。 |
| 兑换网点 | 后台维护门店启停、名称、地址、电话、经纬度；小程序只展示启用门店；拨号和导航读取同一门店详情。缺坐标时不得伪造导航成功，停用门店不可被自提或兑奖选择。 |
| 平台商城 | 商品/SKU/库存与运费规则进入服务端报价；购物车、地址、优惠券、下单、支付回调、发货物流、签收/自提、售后退款贯穿同一订单号；支付通知验签且金额匹配后才算已支付，取消/超时释放库存和优惠券，退款成功回调累计退款并调整佣金。并发下单、重复回调、部分退款和取消竞态须幂等。 |
